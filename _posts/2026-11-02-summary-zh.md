### [AI“分词器税”报告：部分语言 token 消耗最高相差 17 倍](https://clear-languages.org/blog/the-tokenizer-tax) ⭐️ 7.0/10

CLEAR 研究联盟的报告称，主流 AI 分词器对英语和高资源语言更友好，导致相同内容在非英语语言中消耗更多 token。报告举例称，同一句话英语需 13 个 token，马拉雅拉姆语需 26 个，阿姆哈拉语则达 78 个；研究覆盖约 200 种语言，不同语言的 token 消耗差距最高达 17 倍。报告认为，这会推高非英语用户的使用成本、增加响应延迟，并压缩有效上下文容量。上述内容来自 Telegram 二手摘要，原始报告的方法与统计口径仍需核对。

telegram · zaihuapd · 11月1日 16:06

**「为何值得注意」** 这条信息把多语言 AI 的成本差异具体化为 token 消耗差距，并给出英语、马拉雅拉姆语和阿姆哈拉语的对比数字，对开发者和非英语用户有直接解释价值。不过它属于研究/倡议报告摘要，并非模型或平台已宣布的实质更新，影响范围仍待原始报告证实。

**「内容角度」** 可做角度：用同一句多语言文本对比英语、马拉雅拉姆语和阿姆哈拉语的 token 消耗，解释分词器设计与成本、延迟、上下文容量之间的关系，并明确标注数据来自 CLEAR 报告、统计口径待核。

### [LongCat-2.5 发布：1.6 万亿参数原生多模态模型](https://longcat.ai/blog/longcat-2.5/) ⭐️ 7.0/10

LongCat 团队发布原生多模态模型 LongCat-2.5，总参数 1.6 万亿，每 token 激活约 480 亿，面向长程 agent 任务，并在 LongCat-2.0 基础上强化视觉理解与 agentic coding。模型将视觉信号编码为多级离散 token 并与文本统一处理，可完成视觉编程等任务；官网已可试用并接入 API，GitHub 与 HuggingFace 版本尚未开放。现有信息来自 Telegram 转述，尚缺独立评测、基准数据和权重开放信息，实际性能与使用体验仍需核实。

telegram · zaihuapd · 11月2日 03:08

**「为何值得关注」** 这条消息的当下性在于新模型已发布且官网和 API 可用，规格中“1.6 万亿总参数、约 480 亿激活”和原生多模态定位也足够具体。但性能提升、长程 agent 任务表现以及 API 的价格与限制尚未由独立评测或完整文档证实，暂时只能视为待验证的发布信息。

**「内容角度」** 可做角度：围绕“1.6 万亿总参数、每 token 激活约 480 亿”的 MoE 规格与“长程 agent＋视觉编程”的官方定位，整理一份已确认能力与待核实信息清单，重点区分官网可试用、API 已接入这类确定事实，与基准成绩、权重开放、调用价格和限制等尚不清楚的部分。
